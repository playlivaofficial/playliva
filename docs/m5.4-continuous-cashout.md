# M5.4 — Continuous round, precise contact and live cashout value

Baseline: M5.3 `8e8f876be6569844a87d0f7e1b2aa69055661cdb`.
Scope is Island Crash's wager/round split, decimal virtual credits and related UI.
No M6, Slot, new route, partner change, dependency upgrade or asset rewrite.

## Round and wager ownership

The engine's round follows `ready → preparing → kick → flying → falling → impact
→ ready`. Its wager independently follows `none → active → cashed_out/lost`.
Manual or auto cashout locks a personal `CrashResult` and credits it once without
changing the round phase, global multiplier, flight clock or private crash point.
Further cashouts are rejected. The wallet's round lock remains held through the
final impact beat, preventing reset or another wager from starting early.

The original crash deadline still freezes the global multiplier and starts the
M5.3 visual fall. It loses only an active wager: a previously successful result
is retained by identity with no second credit/history entry or loss mutation.
The renderer now uses the global crash multiplier, never the personal cashout
multiplier, to derive the fall's starting altitude and duration. Falling lasts
450–850ms; ready begins 220ms after impact. Neither animation callbacks nor
render success can settle money.

Auto cashout compares logical deadlines, not callback order. A target equal to
the crash point loses. A throttled frame that misses both deadlines first settles
an earlier valid auto target, then starts the final visual fall. Busy and wager
guards preserve manual/auto/reentrant idempotency. RNG, 7000ms exponential growth,
100× cap, stake validation/headroom and the local-only outcome remain unchanged.

## Fixed-point wallet and migration

Schema v2 keeps the same storage key and wallet methods; all balance, debit,
credit, stake, payout and ledger amounts are **integer hundredths**. Initial/reset
balance is 1,000,000 units = 10,000.00 Liva Credits. The cap remains the same
1,000,000,000 credits, represented by 100,000,000,000 safe integer units.

`payoutFor` uses `BigInt(stakeUnits) * BigInt(multiplierHundredths) / 100n`, flooring
only the fractional subunit. The action and settlement use this same calculation:

| Stake | Multiplier | Return |
| --- | --- | --- |
| 10.00 | 1.15× | 11.50 |
| 100.00 | 1.01× | 101.00 |
| 250.00 | 2.34× | 585.00 |

Text inputs parse decimal digits directly into whole/fractional integers, accept
dot or comma and reject exponent syntax or more than two decimals. Locale-aware
display formats integer whole/fractional parts with exactly two digits. No
floating-point balance mutation or currency symbol is introduced.

Migration accepts only known v1/v2 schemas. It validates v1 using the old limits,
reset allocation and ledger continuity **before** scaling. For example, v1's
9750 balance and 250 debit become 975000 and 25000 units, displaying 9,750.00 and
250.00. Valid settings, all bounded ledger entries, timestamps, IDs and sequence
numbers survive. The migrated v2 record is persisted during hydration; v2 reloads
never scale again. Invalid or unknown data uses the existing visible safe reset.
Failed writes retain a usable converted in-memory wallet; retrying unchanged v1
storage does not double-scale. Detected competing tab writes still detach saving.

This is best-effort local entertainment storage, not atomic shared accounting.
Reload starts ready; an unpaid interrupted wager is spent, while an already
credited return stays in saved history/balance. No account, backend, resumed
round, refund or cross-tab monetary guarantee is added.

return; after cashout it becomes disabled and displays the locked return. A small

covering the live multiplier or castaway. EN/PT-BR/ES-MX copy explains continued
flight, subunit rounding and interruption behavior. The 320px action stays 60px

the local-only real-renderer storyboard and skinned-foot/body regression test.

at +16ms forward/upward displacement is clear. No arbitrary timing change was
made. Desktop and actual 320px frozen frames confirm the contact/separation;
the 500ms mobile frame is already predominantly sky. The existing source/runtime
GLBs and all flight/ground calibration data remain byte-for-byte unchanged.

high crash. A deterministic 100× round was inspected at 99.77× flying, +450ms
falling and +900ms impact, retaining the same 115.00 return throughout. A 1.00×
mobile loss has clean ground impact at 450ms. These test controls are not app
routes, production query switches or overrides of live RNG.
